Reladynamo

A generic Reladomo persistence adapter for DynamoDB. Point an existing Reladomo object model at DynamoDB without changing the XML, the generated classes, or a single finder call site — and keep Reladomo's bitemporal semantics exactly.

How it works Source on GitHub Support contract

The idea

Reladomo's bitemporal logic lives in its TemporalDirector, above the persistence layer. By the time a write reaches storage, the director has already decided which rows should exist and hands down plain inserts, updates and deletes that carry their own businessDate and processingDate boundaries.

So Reladynamo does not reimplement bitemporality — it replaces only the persister and inherits everything above it. That makes "the same bitemporal behaviour" something to test rather than assert: one conformance suite runs against H2 (stock Reladomo JDBC, the reference) and against DynamoDB, and the results must be identical.

Quickstart

git clone https://github.com/drompincen/reladynamo.git
cd reladynamo
mvn clean install          # all modules; DynamoDB Local runs in-process, no Docker
bash scripts/check.sh      # the full gate, including the H2-vs-DynamoDB differential suite

Then run a demo. Each is a standalone Maven project that runs against both H2 and DynamoDB:
